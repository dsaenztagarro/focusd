# Guides

**How-to** documents: the steps to do a recurring task in this project — set up a dependency, run a workflow, operate a piece of infrastructure, follow a coding pattern.

A guide is distinct from its neighbours:

- a **guide** answers *how do I do X?* (steps);
- an [ADR](../architecture/decisions/) answers *why is it built this way?* (a decision);
- an [explainer](../architecture/) answers *how does this mechanism work?* (current-state behaviour).

## Conventions

- One task per file, named for the task (`local-setup.md`, `running-migrations.md`).
- Lead with the shortest correct path; put edge cases and troubleshooting after.
- ASCII diagrams only; prose one line per paragraph.
- Link the guide from `AGENTS.md` or the relevant explainer/ADR when it's load-bearing, so it's discoverable rather than orphaned.
